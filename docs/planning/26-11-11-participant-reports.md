| Order | Native behaviour and source | Browser implementation and verification |
|---|---|---|
| 1 | `Store::host_info` returns open publication, operator contact, terms, idle period, size cap and authorised file expiry. [Server store](../../original/figcraft/apps/figcraft-server/src/store/files.rs) · [Native host controls](../../original/figcraft/crates/ui-egui/src/live.rs). | Extend the provider-neutral host-information record and the existing About this server and live-file views. Preserve the actual local size/expiry settings. Test an unspecified contact, plain contact, safe web terms, private/public availability and the per-file deadline. |
| 2 | `collab.report` accepts a non-empty reason from a live server guest. `Hub::message` takes the file, link and address from the actual connection. `Store::keep_report` cleans controls and bidi characters, trims and truncates to 500 Unicode scalars. The operator receives a timestamp, the file ID and name then, the joined link ID, address and reason. The newest 1,000 survive. [Engine command](../../original/figcraft/crates/engine/src/sharing/live/host.rs) · [Native store](../../original/figcraft/apps/figcraft-server/src/store/files.rs). | Route the logical browser tab through its current physical grant. The host validates the login, session, grant lifetime and trusted ingress address. A signed-in stranger cannot submit using another connection. Keep reports operator-only across file deletion and restart. Verify 1,001 reports, action ordering, Unicode, retention, concurrent revocation and authoritative name and address. No report belongs in a document, client-visible table or shared notification. |
| 3 | `Abuse::allow(Action::Report)` charges ten per address per hour with continuous refill, IPv6 hierarchy and atomic all-block admission. Both public and private hosts enforce it. Code guesses, publication and reports share the bounded address eviction table. [Native budgets](../../original/figcraft/apps/figcraft-server/src/abuse.rs). | Reuse the local address normalisation, clock, shared table and eviction logic. Compare first refusal, refill boundaries, competing requests, eviction and database restart with an independent Rust trace. Refused and empty reasons create no report. |
| 4 | `report_ui` exposes Report this file… for a live participant. It focuses the reason, handles Return and Cancel, and shows the server result. [Native UI fixture](../../original/figcraft/crates/ui-egui/src/live_server_tests.rs) · [Native server workflow](../../original/figcraft/apps/figcraft-server/src/public_tests.rs). | Verify with separate owner and viewer in production Chromium: report, cancel, blank reason, operator record, subsequent refusal, no live grant after revoke. Test narrow layout and the normal File/session menu. The host and provider own authority; the command leaves selection, undo history and file bytes untouched. |

After this, trace operator-key publication before implementing team libraries. The native server refuses library publication on an open-host file published without a key. Operator-published files retain the separate edit/view links and the delegated edit link can publish; an ordinary view link cannot. Before adding a host action, map the native operator key to the existing authorised operator boundary. Then implement private library archive revision, authenticated fetch and explicit trust/check, followed by usage and activity reports. [Server library tests](../../original/figcraft/apps/figcraft-server/src/library_tests.rs) · [Publication rules](../../original/figcraft/apps/figcraft-server/src/store/library.rs). Ordered collaboration and the remaining master roadmap follow.
