# Local file workspace, history and branches

## Entry evidence

The production library and style checkpoints supply native archives, a single-document engine and account-scoped device recovery. The reference fork and upstream main both resolved to `a2e87433d8bda2b0c909587da08cb27c51e3b17e` on 10 November. The combined local graph identifies `cycle_doc`, `go_to_library_main` and the current React editor. Row 11 needs independently editable documents. The current host replaces the open document, and its recovery store holds a single archive per principal. The current native decoder rejects archives containing history or branch members. These are observable gaps.

## Implementation order

1. **Document tabs and session identity.** Follow `cmd/file.rs::{new_file,cycle_doc,close}`, `file.moveTab`, `doc.switch`, `doc.list`, `DocState` and `cmd/file/tab_order_tests.rs`. Give each open document a stable session ID, its own document, allocator, undo stack, saved baseline, selection, page and viewport. Keep inactive tabs free of active canvases and event listeners. Drive opening, selecting, cycling, reordering, closing and the no-document state from one workspace command boundary. Preserve the existing standalone engine entry points. Compare native results for clean and dirty documents, closing before the selected tab, index errors and wraparound.
2. **Opening, saving and recovery.** Map `cmd/file/{open,load,save}.rs` and the web recovery implementation to explicit file selection, native downloads and the host recovery adapter. Switching tabs during a file read, download, image decode or recovery write must preserve its original destination. Verify all tabs restore in order under the same principal. Read the existing single-archive recovery format. A closed tab must stay closed after a late write. Test local storage failure and separation between two signed-in users. Include recent files, duplicate, rename, revert, thumbnails and dirty-close confirmation.
3. **Linked source navigation and clipboard.** `cmd/component.rs::go_to_library_main` finds the source file, opens or activates it, verifies its publication identity and selects its original component. An open author tab or an explicitly selected author file supplies editable source. The existing cached publication contains only published assets. Cover removed links, missing files, replaced publications, renamed or removed mains and variants. Reuse the same file identity for cross-file paste and preserve dependency IDs and library records from `assets/library.rs`. Track cross-file clipboard conformance against row 3.
4. **Version history.** Follow `cmd/file/version.rs`, `version_tests.rs`, `version_preview_tests.rs`, `format/src/version_tests.rs` and `ui-egui/src/panels/versions.rs`. Preserve named and automatic snapshots, current page, ordering, limits, metadata, preview, duplication, restore and deletion. Version records sit outside ordinary document undo. Verify real native archive members and inspect the independently reopened Rust file.
5. **Branches and conflict review.** Follow `engine/src/sharing/branches.rs`, `branch_tests.rs`, `branch_versions_tests.rs`, `format/src/branch_tests.rs` and the branch UI tests. Record branch ownership by main tab ID, persist branch edits in the main file, compare changes, resolve individual conflicts and retain pre-merge history. Test a mixed conflict against native results. Live branch propagation depends on row 14’s ordered collaboration and grant checks.
6. **Local release gates.** Check active and inactive memory use, late callbacks, serialised size, switching latency and keyboard and pointer workflows with several substantial documents. Use real Supabase host Auth, native interchange, desktop and narrow Playwright tests, fixed visual samples and a property report. Server ownership, share grants, durable remote files and live editing remain assigned to rows 13 and 14.

The first implementation boundary is the tab lifecycle and per-tab editing state. Validate the scoped Figcraft MCP connection before advancing from the entry checks. No table or new Auth capability is justified by local file tabs.
