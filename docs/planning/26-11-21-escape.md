## Native contract

`crates/engine/src/canvas/tools/keys.rs::escape`, in order: stop following a collaborator; end the pen; cancel a gesture; dismiss the placement crosshair; end moving the rotation origin; leave text editing; leave vector editing (or end its pen path); return to the Move tool; leave the focus view; and last, clear the selection.

Upstream measured the target application: with a layer inside a group inside a frame selected, one Escape selects nothing. Before, native selected the parent first.

## What the port had

Escape lived in the editor's key handler. It handled following, crop, the pen, the shape builder and vector editing, then cancelled a gesture and ended moving the rotation origin. It never touched the tool or the selection: it neither selected the parent nor cleared the selection.

## Hazards and known differences

- The canvas has its own key listener that cancels a gesture on Escape, before the editor's handler runs. Without care the same key press would then also clear the selection. The canvas now stops the event when a gesture was in progress; an existing browser case for smart gaps caught this.
- The port has no placement crosshair and no focus view; those two branches have no counterpart.
- Text editing and following a collaborator end through their own key handling in the port, before this function is reached.
