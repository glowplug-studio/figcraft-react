## Native evidence before implementation

The online list belongs to the device and principal. The server validates ownership for the recorded file IDs. A fresh device has an empty list. Forgetting a live file never deletes it from the server or causes refresh to rediscover it. Listing alone sends no request. A refresh batches at most 200 IDs per server. Loading saved preferences examines the first 800 records, keeps the first usable entry per server and file, and discards server state and expiry from the previous run. An unavailable server preserves the local row. A successful lookup that omits it marks it gone. Opening an already joined file reuses its document tab. [Native ownership tests](../../original/figcraft/crates/engine/src/online_tests.rs).

At publish time the server also cleans the document's internal name. It trims the chosen name, removes controls and bidi formatting characters, keeps 256 Unicode scalars, and falls back to the cleaned document name. Later rename only edits the listing and rejects an empty cleaned name. Compare both the published archive and the saved source document, including separate tabs. The default owner edit/view links and optional shared edit/comment/view links have separate lifetimes. Stopping sharing preserves the owner's ability to open the file. Public dashboard summaries omit tokens, including in offline and error results. [File store](../../original/figcraft/apps/figcraft-server/src/store/files.rs) · [Server name policy](../../original/figcraft/apps/figcraft-server/src/store.rs).

Join-code compatibility was sampled directly from the pinned standalone Rust code. The reference includes Crockford look-alikes, Unicode whitespace, the 128-byte limit, local address and port, 44-bit secrets, folded FNV check bits and single-symbol transcription errors. Run these comparisons before testing a live invitation. Compare the browser invitation fragment, online lookup and local transport independently. [Join-code reference](../../original/figcraft/crates/collab/src/code.rs).

The hosted project URL and active publishable key were verified through the scoped MCP. Its public schema still has zero tables at this checkpoint. Storage uses a private bucket, per-operation policies and authenticated downloads. Opening and removal must immediately lose access after revocation. [Supabase Storage access control](https://supabase.com/docs/guides/storage/security/access-control).

## Local database design
The first private bucket is `figcraft-files` (16 MiB public-host limit). The client uploads one immutable native archive to its own principal and file UUID. Possession of a UUID grants no access. A validated server operation obtains the object through the owner's authenticated client, checks the archive and its limits, and commits metadata against the exact Storage object ID. A foreign key prevents a visible listing for a missing or replaced object. Removing the snapshot through Storage cascades its listing. The database denies direct client inserts and limits owner updates to the listing name. Retry the same operation ID and archive after a lost response. Test concurrent publication and replacement while validation is in progress.

Exercise each policy with real local Auth, including direct column updates and forged ownership. Prove that the bucket denies public reads, anonymous writes, a second user's reads/writes/deletes and upserts of a published snapshot. Exercise interrupted uploads, invalid archives, successful validated finalisation, rename without changing the interior title, removal, and cleanup of abandoned uploads. Repeat with shared access when its grants land. The provider's DDL tool tracks policies on `storage.objects`. Buckets are data, configured separately from schema declarations. [Supabase declarative schema limitations](https://supabase.com/docs/guides/local-development/declarative-database-schemas#supabase-managed-schemas).

The 2.116.0 generator placed the column UPDATE grant before a table-level REVOKE and omitted the anonymous revoke. A rolled-back PostgreSQL 17.6 probe confirmed the original ordering removed the name update privilege. The local project also gives anonymous users table privileges by default. The reviewed migration explicitly revokes all client table privileges first and then grants authenticated SELECT and name-only UPDATE. Verify the effective table, column and function ACLs after local replay, including TRUNCATE and REFERENCES.
