## Native evidence before implementation

The online list belongs to the device and principal. The server validates ownership for the recorded file IDs. A fresh device has an empty list. Forgetting a live file never deletes it from the server or causes refresh to rediscover it. Listing alone sends no request. A refresh batches at most 200 IDs per server. Loading saved preferences examines the first 800 records, keeps the first usable entry per server and file, and discards server state and expiry from the previous run. An unavailable server preserves the local row. A successful lookup that omits it marks it gone. Opening an already joined file reuses its document tab. [Native ownership tests](../../original/figcraft/crates/engine/src/online_tests.rs).

At publish time the server also cleans the document's internal name. It trims the chosen name, removes controls and bidi formatting characters, keeps 256 Unicode scalars, and falls back to the cleaned document name. Later rename only edits the listing and rejects an empty cleaned name. Compare both the published archive and the saved source document, including separate tabs. ## Local database design

A validated server operation obtains the object through the owner's authenticated client, checks the archive and its limits, and commits metadata against the exact Storage object ID. A foreign key prevents a visible listing for a missing or replaced object. Removing the snapshot through Storage cascades its listing. The database denies direct client inserts and limits owner updates to the listing name. Retry the same operation ID and archive after a lost response. Verify that a retired credential still cannot grant access after a restart.
2. Reproduce admission before key stretching. A single IPv4 address or IPv6 /64 gets ten attempts per minute. Wider IPv6 /56 and /48 budgets are scaled by two and four. Wrong guesses accumulate until decay or lockout. Correct guesses do not reset the wrong count. The global wrong-code bucket holds 1,000 and refills over an hour. Integrate with verified ingress addresses. Reproduce the native clock-boundary, cross-address, concurrent and malformed-code cases. A blocked code lookup must leave long-link joining usable.
3. Accept a bare normalised code and native code invite in the signed-in join form. With two accounts, open the same drawing once per role, verify edit restrictions, stop sharing, retry each code, then restart and use a new code. Keep raw codes, bearers and seeds out of logs and document snapshots.

The authenticated host resolves the ingress address. On Vercel it uses the single platform-provided `x-vercel-forwarded-for` address. The local host shares one loopback budget, and ignores forwarded address headers. Database roles prevent a browser choosing its own address or clock. The private RPC admits an attempt, stretches the key, unwraps the exact credential and accounts for the result in one transaction across all host workers. Private retirement digests and wrong-code budgets expire with the database process. A full invite still goes through its existing guest permission checks independently.
