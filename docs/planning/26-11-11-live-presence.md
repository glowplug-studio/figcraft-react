# Live presence and signals

Roadmap row 14. The pinned [wire protocol](../../original/figcraft/crates/collab/src/message.rs) carries a page-relative cursor, selected IDs, page viewport and optional text caret/selection. [Session capture](../../original/figcraft/crates/engine/src/sharing/live/events.rs) returns empty presence for inactive documents. [Sanitisation](../../original/figcraft/crates/engine/src/sharing/live.rs) removes invalid geometry and caps selection at 10,000. The [native throttle](../../original/figcraft/crates/collab-net/src/throttle.rs) coalesces pointer changes at 33 ms. Cursor chat, spotlight and display names each have separate validation and state. Track connection loss, follow/unfollow and peer departure.

1. Reuse the live grant for authority. Derive sender identity and the current recipients on the trusted host. Deliver transient state only to current private physical connections. The [Supabase Broadcast documentation](https://supabase.com/docs/guides/realtime/broadcast) describes HTTP-to-WebSocket delivery. Do not retain presence in drawings, the edit log or database broadcast rows. Reuse the connection observer and keep transport contracts provider-neutral.
2. Add native validation and coalescing cases, exact large IDs, viewport/cursor sanitisation, bounded names and chat, and cross-account, wrong-session, revoked and replaced-tab security tests. Cover late joins and recovery of the current state after missed delivery.
3. Expose pointers, peer selections and typing, people, rename, follow and spotlight in desktop and narrow editors. Verify ephemeral actions produce no drawing or undo changes, label collisions in multiple tabs, viewport updates under pan and zoom, inactive tabs, disconnects and cleanup. Use the real private transport in production Chromium and local provider tests before publication.
