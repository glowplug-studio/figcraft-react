# Upstream delta row 2, item 12: Escape

21 November 2026 · Branch `prompt/full-figcraft-port`. Native reference `bad07e4433240cad046589129c084bd2fc36f097`. Implementation `2cb640a`. **This bounded item passes. Seven items of row 2, the other delta rows and the full port remain unfinished.**

## Implemented boundary

Upstream `a285fd29` and `92cf9849` made Escape clear the selection whatever its nesting; native used to select the parent first. The port did neither: its Escape cancelled a gesture and ended moving the rotation origin, and left the tool and the selection alone.

[`EditorEngine.escape`](../../src/engine/editor.ts) now carries native's order from the pen onwards: finish the pen, cancel a gesture, end moving the rotation origin, leave vector editing, return to the Move tool, and last clear the selection. The [editor](../../src/Editor.tsx) calls it for Escape on the canvas.

- With a layer selected, however deep, one Escape selects nothing.
- With another tool chosen, Escape returns to Move first and keeps the selection; the next Escape clears it.
- In vector edit mode, or while the rotation origin is being moved, Escape ends that first and keeps the selection.
- An Escape that cancels a drag is used up by it: the [canvas](../../src/engine/canvas.ts) stops the event, so the same press does not also clear the selection.

## Verification corrections retained

The first build cleared the selection when Escape was pressed during a smart-gap drag. The canvas has its own key listener, which cancelled the drag first; the editor's handler then saw no gesture and treated the same press as the Escape that clears the selection. The existing browser case `smart canvas gaps preview without root renders and cancel on Escape` failed on it. The canvas now stops the event when a gesture was in progress, and the case passes.
